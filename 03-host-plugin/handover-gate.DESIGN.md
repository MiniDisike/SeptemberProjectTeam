## 0. 一句话

**两条闸，都是 `tools/pre-execute` 的 deny**（工具调用在派发前就变成 `isError`），
外加写闸收尾侧的一条 `agent.steer()`（让 agent-loop 的收尾 `break` 不成立）。
**没有任何一条靠提示词。**

⚠ **两处口径（R43 返工改的事实，旧稿写错过）**：

* **不是"零上下文注入"**：本插件**不注册任何持续通道**（没有 `systemPrompt` / runtime context /
  消息通道注册 —— 自检 ㉔ 用 Proxy 逐次记录证明），但写闸的收尾侧 `agent.steer()`
  **每次都会塞一条 `role:"user"` 消息进上下文**：
  实测 **499–563 字符 / 812–877 字节 ≈ 234–253 token/次**（1–2 个脏路径；粗口径 字节/3.47），
  上限 **≤1 次/回合、≤2 次/会话 ⇒ ≤488 token/会话**。
  极端情况（脏路径列满 12 条）单次可到 1206 字符 / 1530 字节 ≈ 441 token ⇒ 会话上限约 882 token。
  `WARDEN_HANDOVER_STEER=off` **每次现读**，一行关掉。
* **不是"运行时只读盘"**：本插件**会 append 一个自己造的事件行文件**，落点与条件见 §4 末。

## 2. 写闸：我选了哪条路 —— 拦得住什么、拦不住什么（**如实**）

派单要求先调研「一轮结束」有没有可拦的水位。**调研结果：没有 deny 这条路。**

```
dsh-agent-loop\lib\index.js:967
    if (turnEnds && this.inbox.nextStep.length === 0) {
        await this.dispatch.serial("agent/turn-stopping", { turn, signal });
        signal.throwIfAborted();
    }
    if (turnEnds && this.inbox.nextStep.length === 0) break;
```

* `serial`（`dsh-agent\lib\index.js:231-233`）——**返回值被调用方丢掉**。
  所以「在 `turn-stopping` 里返回 `{kind:'deny'}`」**什么也不会发生**。
  （唯一能让它"有反应"的写法是**抛异常**，但那是 `:976 catch` → `turnEnds={kind:'error'}`
  ⇒ 把整个回合标成 error，不是"不许完成"。**故意不用**。）
* 但 `:973` 那一行的 `break` 是**可以被代码否掉**的：往 `inbox.next-step` 塞一条即可。

### 我选的路（两条一起用）

**A. 收尾侧：`agent.steer()` —— 真的阻止收尾。**
`steer` ⇒ `send(msg,'next-step',true)` ⇒ `inbox.splice('next-step',…)` ⇒ `:973` 的
`nextStep.length === 0` 不成立 ⇒ **回合结束不了**。这不是"提醒"，是 agent-loop 的
收尾条件被代码否掉。

| 拦得住 | 拦不住 |
| --- | --- |
| 在"改了文件却没更新交接"的回合上**继续跑**（模型必须再做一步） | 拦不住"模型就是不写交接"—— 它只是不能在这一步收尾 |
| 上限极小、可重复验证：每回合 1 次、每会话 2 次（`steerMaxPerTurn` / `steerMaxPerSession`） | 如果 steer 消息的形状 DSH 不接受（`agent.steer` 抛错），**只记一行失败，不放环** |
| 只有"真有脏文件"才触发；干净回合一个字都不说 | 不改文件、不改交接的纯问答回合**完全不触发** |

**B. 硬 deny 侧：下一次改盘动作被拦 —— 这一条是无条件的、不会成环的。**
`turn-stopping` 里认出「上一轮改了 N 个文件（逐条列路径）却没更新交接」⇒ 记下欠账；
**下一轮第一次 `write`/`edit`/`str_replace_editor`/`pwsh`（**整个 shell 类**）/`present` 一律 deny**，
理由里列出那 N 条路径 + 交接的绝对路径 + 逐字三条硬规矩。

⚠ **欠账的键是"工程根"，不是会话 id**（R43 返工 S1）：旧稿按 sid 存 ⇒
**子代理改了文件、父会话完全看不见**（审查实测 `E11 {"turnRow":null,"steers":0,"pending":null}`），
而本项目 R19 就是"编程活派给子代理" ⇒ 写闸可被最常用的工作方式**整条绕过**。
现在按工程根汇总，**子代理改的盘，父会话的下一次改盘动作也会被拦**（自检 S1a–S1d）。

⚠ **脏账的键是 `sid:turn`**（R43 返工 S2）：旧稿键是 sid、只在 turn-stopping 里 delete，
而 `:941` reject / abort / `:945` / `:976` 都会**跳过** turn-stopping ⇒
**记账跨回合泄漏、写闸被静默关掉**（审查实测 `E16 {"ev":"clean","handoverTouched":true,"dirty":1}`）。
现在按回合分桶，并且**收尾 `turn <= 当前` 的所有桶**（自检 S2a–S2f）。

| 拦得住 | 拦不住 |
| --- | --- |
| "改了文件不写交接就当完成" —— 下一轮**任何**改盘动作、**任何** shell、`present` 都过不去 | 它拦的是"**下一次动作**"，不是"**这一轮不许结束**"（后者由 A 负责） |
| 不依赖任何事件语义 ⇒ 事件形状改了它仍然有效 | 欠账只能靠**写那一份交接**来清（这是有意的：唯一解锁方式；写别的 `交接-*.md` **不清**，0 字节写**被拒**） |
| 与 A 互补：A 若被关掉（`WARDEN_HANDOVER_STEER=off`）或 steer 失败，B 仍然拦 | 一个"永不写交接"的会话会被卡住 —— 这是硬规则的**代价**，逃生阀是 `WARDEN_HANDOVER_STEER`（**每次现读**）/ 卸载插件，**不是**放宽判据 |
| 跨会话（子代理）与跨回合（turn-stopping 被跳过）都算得到 | 子代理回合**被 reject/abort** 时 root 欠账不会建立 —— 残余缺口，见 §11 |


### 为什么默认开着 A 不会重演 I60（warden-watch 的 steer 事故）

I60 的根因是「**红是结构性的、修不掉**」⇒ steer 接了也永远修不绿 ⇒ 回合永远结束不了
（实测：新窗口 43 次工具调用 / 26 步 / 20 分钟，用户手动停掉）。
本闸的 steer 条件是「**写一次交接文件**」—— 一个**可执行、一步就能做完**的动作，
而且上限是**每回合 1 次 / 每会话 2 次**（进程内存计数）。
最坏情况：一个会话多跑 2 步。想彻底关掉：`WARDEN_HANDOVER_STEER=off`（一行环境变量，不必改代码）。

## 3. 读闸（硬）

* **判据**：`tools/result` 里出现一次 **成功的 `read`**、其 `file_path` **正好等于**
  当前工程根解析出来的那一份交接文件 ⇒ 该会话对该文件记为"已读"。
  ⚠ **"成功"的口径收紧了（R43 返工 S5）**：`result` 必须**是对象**且 `isError !== true`；
  旧稿 `!(result && result.isError === true)` 把 `result === undefined` 当**成功**
  ⇒ 形状一变就会把失败的 read 记成"读过"（自检 S5a/S5b）。
  ⚠ `exec.agent` 缺席 ⇒ **不记"已读"** + 失败行 `agent-missing`（旧稿让所有无 agent 调用
  共用 `anonymous` 桶 ⇒ 一次 read 解锁全部，S5c/S5d）。
* **模型自述不参与判定**（R43 必须③）：判定只看 `exec.name` / `exec.arguments.file_path` /
  `result.isError`，**不读任何助手文本**。
* **范围克制**（否则死锁）：只拦会**改盘**的动作 ——
  `write` / `edit` / `str_replace_editor`，以及**整个 shell 类**（`pwsh`/`bash`/`sh`/`shell`/`cmd`/`run`/`exec`）。
  `read` / `read_image` / `glob` / `grep` / `todo_write` / `skill` / `subagent`
  **零 IO 直接放行**（`present` 只受写闸管，见 §3 末）。自检 ⑥⑦ 两条负控钉住。
* ⚠ **未读交接时整个 shell 类都拒**（R43 返工 S5）：
  旧稿只认命令文本里的写关键词，于是 `pwsh -Command "node -e \"fs.writeFileSync(...)\""`
  **既不触发读闸也不触发写闸** ⇒ 能整条绕过 R43 改工程文件。现在不赌关键词：
  未读 ⇒ `pwsh`/`bash`/… 全拒（自检 ⑧/⑧a）；读**过**之后只读命令放行（自检 ⑧b，死锁负控）。
  理由里给**逐字可抄的交接绝对路径**，并写明"读交接不需要 shell"（所以不死锁）。
* **两条共同豁免**（也是死锁负控，自检 ⑬⑬b）：
  工程根下的 `交接.md` / `交接-*.md` **永远可写** —— 否则"没读过 ⇒ 不许改盘"会把
  "创建/更新交接"这个补救动作本身也拦死。
  ⚠ 但**豁免 ≠ 解锁**（R43 返工 (4)）：只有**解析出来的那一份**才算"更新了交接"
  （写无关的 `交接-scratch.md` **不清**欠账，自检 (4)a）；
  而且 **0 字节写会被直接拒**（自检 (4)b/(4)b2）。
* **`present`（声明交付）只受写闸管**（R43 返工 S4）：它**不写盘**，所以不受读闸管；
  但它就是"声明完成"这个动作 ⇒ 有欠账时**被拦**（自检 S4a/S4b）。
* 交接文件**不存在**时：**fail-closed（拒绝）+ 记一行失败** `handover-missing`，
  理由里说清"这个工程里**没有**交接文件"（与"没读到"分开）并给出应当新建的绝对路径。
  **自检 ⑭ 把这条选择钉住了**（另一条路是"放行 + 记失败"，我没选）。

## 4. 交接文件位置：运行时解析（R43 ③ / R40 ②）

工程根（与 `warden.mjs` 的 `findProjectRootVia` **同约定**，只读参考、**没有** import 它）：

```
向上找最近的 .git              ⇒ via:'git'              （正路）
一路没有 .git，退而取最近的 .warden ⇒ via:'self-warden' / 'ancestor-warden'
都没有                          ⇒ { root:null, via:'unresolved' }
```

⚠ **与 warden.mjs 的一处有意不同**：什么都没找到时 warden.mjs 返回 `{root:start, via:'self'}`
（它必须给个目录才能干活），本闸返回 `root:null` ——
因为对本闸来说"推不出工程根"和"工程根就在这儿"**必须分得开**，
返回 `start` 会让"推不出"伪装成一个正常根，那就是静默失效。

交接文件的两个名字与"最新"的口径：

```
① <root>\交接.md          —— 首选（命中即返回，不做 readdir）
② <root>\交接-*.md        —— 取最新的一份
   "最新" = 名字里的 ISO 日期键大的在前 → 同/无日期比 mtimeMs → 再比文件名
   ★ R43 返工（S10）：月/日**不补零也认**（`交接-2026-9-24.md`），键**补零后**再比；
     非法月/日（`交接-2026-99-99.md`）仍返回 ''（不许拿垃圾名字赢过真日期）
```

**为什么日期优先于 mtime**：交接文件的语义是"哪一天的交接"，不是"这个文件什么时候被拷过来"。
本工程就是活的反例：`交接-2026-09-24.md`（今天）与 `交接-做成DSH插件.md`、
`交接-补充给插件窗口.md`（09-16 的旧件）并存；**自检 ②b** 证明"纯按 mtime 会挑错人"
（mtime 最新的是 `交接-做成DSH插件.md`），而日期键单独就能挑对。
⚠ 旧稿只认 `\d{2}`，于是 `交接-2026-9-24.md` **不被认成日期 ⇒ 静默退回 mtime** ——
名字里明明写着日期却不认，等于把口径偷偷退回 mtime（自检 S10a/S10b/S10c 钉住）。
自检 ④ 用**只读**方式验证：本工程解析出的就是 `<WORKSPACE>\task-warden\交接-2026-09-24.md`。

**不许静默失效**（每一条都有自检）：

| 情形 | 行为 | 自检 |
| --- | --- | --- |
| 交接文件不存在 | **deny** + 失败行 `handover-missing` | ⑭⑭b⑭c⑭d |
| 工程根推不出 | 失败行 `root-unresolved` + 放行（"推不出"没有参照物） | ⑮⑮b⑮c |
| 根是祖先的 `.warden`（静默路） | 失败行 `root-via-ancestor-warden`，理由里写明 `via` | ⑯⑯b |
| 判据内部抛异常 | **fail-open 放行** + 失败行 `pre-execute-threw` | ㉖ |
| `result` 不是对象 | **不认这次结果** + 失败行 `result-shape-unknown` | S5a/S5b |
| `exec.agent` 缺席 | 不记账 + 失败行 `agent-missing`（写侧 fail-closed） | S5c/S5d |
| 回合号推不出 | 继续记账 + 失败行 `turn-unresolved`（S2 的修复会退化，必须看得见） | 插件内 `fail()` |
| `agent/pre-step` 没带 turn | 失败行 `pre-step-turn-missing` | 插件内 `fail()` |

失败行的三个出口：`state.failures`（可读）、stderr（**不进模型上下文**）、
**事件行文件**（落点见下）。
同一 `(ev,sid,gate,tool,target)` **3 秒内只落一行**，防 deny 风暴刷爆日志。

### 事件行文件到底写在哪（R43 返工：这是**事实口径**，旧稿"只读盘"是假话）

本插件**会写盘**，只写**一个它自己造的事件行文件**（deny / 失败 / steer / 回合脏 / 读交接）。
按顺序取第一个可用的落点：

```
① opts.logPath（显式，自检传的）                       —— 无条件用
② WARDEN_HANDOVER_LOG（显式）                          —— 无条件用
③ <root>\.warden\HANDOVER-GATE.jsonl                   —— **只在 `.warden` 目录已存在时**
④ %TEMP%\handover-gate.jsonl（os.tmpdir()）             —— 上面都不成立时的退路
```

⚠ **绝不 mkdir**：非显式路径要求**父目录已经存在**，不存在就往下一条候选退。
⚠ **实测（审查）**：不给 `logPath` 时，在被审工程里跑会得到
`logPath=<WORKSPACE>\task-warden\.warden\HANDOVER-GATE.jsonl`
⇒ **插件会往被审工程里 append 一个它自己造的新文件**。这就是事实口径。
允许路径永远可写豁免，所以这条落盘**不会**和读闸/写闸打架。

## 5. 三条硬规矩（R43 必须⑤）—— **三条逐条**从权威源机器抽取

逐字常量在 `handover-gate.js` 的 `HARD_RULES`，**每一条 deny 的 `reason` 都原样带上**（不加前缀，整行可 grep）。
⚠ `HARD_RULES` 是 **4 行**（3 条规矩）—— 因为**第 1 条在权威源里本来就是两行**：

```
第 1 条（两行）：
✗ 错写法：「只改你点名的文件」                      ← 会诱导你直接改真文件
✓ 正写法：「只改 .warden/patches/<ID>/work/ 里的副本；**真文件一个字节都不许动**」
第 2 条：不许用"加提示词"来解决任何问题
第 3 条：测副本必须把 DSH_HOME 指到镜像
```

**权威源 = `<WORKSPACE>\task-warden\派单模板.md`**（"派单前从这里抄，不凭记忆"的那个文件）。
自检 ㉓ **读那个文件、按行号机器抽取**，与 `HARD_RULES` **逐条 `===`**：

```
第 1 条 = L13（错写法行）+ L14（正写法行）  —— **照两行，不拼**
第 2 条 = L18（标题行，剥掉 `## ⚠ `）
第 3 条 = L22（标题行，剥掉 `## ⚠ `）
抽取规则只有一条：有行首 markdown 标题装饰就剥掉，**其余一个字符都不动**
（不拼接、不加 U+3000、不剥 `**`、不改引号、不补句号）
⇒ 第 3 条**没有**"（否则 lab 会跑真原件）。"那句 —— 那是旧稿自己加的压缩/扩写
```

⚠ **为什么不取 L53**：L53 是"标准结构"示例里的列表项，措辞**少一个「来」**
（`不许用"加提示词"解决任何问题`）且带 `- ⚠ **…**` 装饰 —— 两行措辞不同，
**能逐字对上的只有 L18**。自检 ㉓e 把这件事钉成证据（打印 L53 的抽取结果）。

⚠ **R43 返工的现场（本项目 A5「不许拿听上去合理的解释代替核实」的实例，两个错叠在一起）**：

## 11. S1 的取舍：我选了 **(a) 按工程根汇总**，并如实申报残余缺口

派单给了两条路：(a) 按**工程根**汇总 dirty，让父会话也能看见子代理改过哪些文件；
(b) 如实申报"本闸只覆盖本会话直接改盘"。**我选 (a)，并在下面把 (a) 也盖不住的地方申报清楚。**

**为什么选 (a)**：

1. **本项目 R19 就是"编程活派给子代理"** —— 这是**最常用的工作方式**。
   选 (b) 等于承认写闸在这条主路上**整条失效**（"必须②"就没了）；
   而 R43 的用户原话是「把写交接与读交接写进**硬规则**」。
2. **交接文件本来就是"工程的"共享物**，不是"会话的"私产：工程根下只有一份"最新那份"。
   既然读闸要的是"本工程那一份"，写闸的欠账按**同一个键**（工程根）记才是同一套语义。
3. **(a) 不动任何别的文件**：判据、状态、理由文本都在本插件里；
   选 (b) 要改 `DEVIATIONS.md`（**不在本单授权内**）。

**怎么实现的**：`pending` 的键从 `sid` 改成 `pathKey(工程根)`；`cur` 的键从 `sid` 改成 `sid:turn`，
值里按 `rootKey` 分槽。于是：子代理改盘 ⇒ 它的 `turn-stopping` 把欠账写到**工程根**上 ⇒
**父会话的下一次改盘动作被 deny**（自检 S1a–S1d 实测）。

**残余缺口（如实申报，不许不修也不申报）**：

* 子代理的回合**被 `:941` reject / abort**（turn-stopping 被跳过）时，**root 欠账不会建立**
  ⇒ 父会话看不见这一次。此时只有**那个子代理自己的**下一次改盘会被"陈旧脏桶"扫描拦住
  （自检 S2e 证明 `agent/pre-step` 一到新回合就会收尾，但那只在**子代理自己**有 pre-step 时成立）。
* 为什么不把"陈旧脏桶"扫描也按根跨会话做：**回合号在会话之间不可比**
  （父会话 turn 3、子代理 turn 1 是常态），按根跨会话比大小会**误拦正在干活的另一个会话**。
  这个取舍写在这里，接受复核。
* `subagent` 工具本身**不算改盘**（零 IO 放行，自检 ⑦）—— 这是有意的：
  它不直接写盘；它派出去的子会话写盘由上面这条链路负责。
