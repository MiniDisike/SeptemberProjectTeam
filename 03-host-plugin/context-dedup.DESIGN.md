## 0. 一句话概括

在 `tools/post-execute` 上挂一个 **prepend** 监听器，在结果进上下文之前把它的 `content` 换成更短的一份；
再在 `agent/pre-step` 上挂一个监听器，对**已经在 surface 上**的 tool/result 节点做同一套判定并按
DSH 自己的 `compaction/prune` + `surfaceOp.replace` 形状改写。
两个档：**逐字节相同 ⇒ 整块换一行指引**；**相似 ⇒ 逐行剔除重复行、只推差异行**（每个被省的行留一个
指向"第一次出现那一行"的占位符，所以能逐字节拼回原文）。

## 2. 算法

### 2.1 归一化与指纹

- `normalizeNewlines`（`context-dedup.js:88`）只做一件事：`CRLF` / `CR` → `LF`。
  **故意不 trim、不去空行** —— 否则"归一化"就变成有损的了。
- `fpOf`（`:105`）= 归一化后的 `sha256`（十六进制）。**内容变一个字节，指纹就变。**
- ⚠ 所以「相同」档的不变量精确表述是「**归一化行尾后**逐字节相同」。
  只有行尾不同 ⇒ 视为相同（自检 **T15** 把这条行为固定下来）。
- ⚠ **出处别记错**：这条归一化写在**任务书**里
  （`角色发言\2026-09-24\2026-09-24_6b995737_你是 实现工程师 。本单要新.md:86`
  的「逐字节相同（归一化后指纹相同）」）。
  **用户 R41 的逐字原话里没有这句** —— `.warden/SPEC.md:565` 只有「可否增加一个功能…」。
  （本文件早先把这句写成"用户 R41 原文明确允许"，那是**张冠李戴**，已改。）
- ⚠ **如实写清：归一化 `CRLF→LF` 不是零字节损失。**
  T15 把 CRLF 那份当「相同」档省掉之后，**能取回的是 LF 那份**（不是被省掉的那份 CRLF）。
  任务书允许这么做，但"零信息损失"在这条路径上要打个折：
  丢掉的只是**行尾字节**，正文内容一个字节不差（`:88` 的注释里也写了这条）。

### 2.2 「非平凡行」的定义（只有非平凡行才允许被按行省略）

`isTrivialLine`（`:156`），平凡 = **一定会被原样推上去**：

1. `line.trim()` 后长度 `< minLineChars`（默认 12）⇒ 平凡。
   含空行、短行、以及我们自己的占位符（`[dup:1:2]` 是 10 字符）。
2. `line.trim()` 后不含任何"实义字符" ⇒ 平凡。
   实义字符集 = `MEANINGFUL_RE`（`:155`）：ASCII 数字/字母 + 拉丁扩展 + 希腊 + 西里尔 + CJK + 假名 + 谚文。
   ⇒ 纯括号 `}});`、纯大括号、纯分隔线 `----` / `====` / `****`、纯标点都算平凡。
3. 其余 ⇒ 非平凡，允许被省略。

⚠ **索引的键是"原样行文本"（不 trim）**（`:370`、`:442`）。
如果按 trim 后的文本当键，重建出来的缩进就会和原文不一致 —— 那就成了有损的。
代价：缩进不同 = 不认为是同一行 = 少省一点。**这是刻意的取舍：宁可少省，不许有损。**

### 2.3 档一：「相同」（整块去重）

`decideRewrite`（`:388`）里 `:397`–`:416`：

1. `idx.liveDup.get(fp)` 命中，且命中者**不是自己**（`hit !== selfBlockId`，`:402`），
   且它确实是"原样块"（`rec.verbatim === true`，`:404`），且它没被体积剪枝护栏挡下（`:405`）
   ⇒ 换成一行指引（用户给的格式，逐字照抄，`:406`）：

   ```
   [与第 N 次 <tool> 的结果逐字节相同，已省略 <X> 字符；原文在上下文里]
   ```

   - `N` = 那个 owner 在**同一工具名下**是第几次结果（`nextBlockId` `:311` 记账）。
   - `X` = 被省略的原文码点数。
   - 只有 `指引码点数 < 原文码点数` 才换（`:408`），否则原样放行。
   - ⚠ **加固（本轮 R41 返工 ③）**：命中还必须**同时被 `idx.liveBlocks` corroborate**
     （`:402` 里那一段 `idx.liveBlocks.has(hit)`）。`liveDup` 与 `liveBlocks` 只在
     "块被撤出 `liveBlocks`、却还留在 `liveDup` 里"时分叉 —— 而那正是唯一能让
     "原文在上下文里"变成假话的分叉（撤出时 `liveDup` 的删除是**有条件**的，`:741`）。
     **少省一点，绝不写假话。**
2. `liveDup` **只装"此刻还活着"的块**（`markLive` `:801`；全量重建见 `:641`–`:649`）
   ⇒ 第一份不在了就查不到 ⇒ 不省。**这是硬约束 5 的落点。**

### 2.4 档二：「相似」（按行重叠剔除）

`decideRewrite` 里 `:424`–`:492`：

1. `cfg.similar !== true` ⇒ 整档关掉（`:426`）。**这是"照旧全文推"那个开关**（见 §7.1 的歧义说明）。
2. 原文里**任何位置**出现占位符形状（`MARKER_ANY_RE`，`:428`）⇒ 整块照推。
   防的是"重建歧义"：如果原文里本来就有一行长得像 `[dup:1:2]`，重建时会把它当成占位符换掉 ⇒ 有损。
   **宁可不省，绝不猜错。**（自检 **T16**）
3. 逐行走（`:435`–`:462`）：
   - 平凡行 ⇒ 原样保留。
   - 非平凡行、且 `idx.lineOwner` 里有 owner、且 owner 不是自己（`:443`）、
     且 owner **此刻确实活着**（`idx.liveBlocks.has(own.blockId)`，`:445`）、
     且 owner 没被体积护栏挡下（`:448`）⇒ 换成一个占位符：

     ```
     [dup:<owner块号>:<该行在 owner 那份文本里的行号>]
     ```

     ⚠ `:445` 那条"owner 必须此刻确实活着"是**本轮返工 ③ 的加固**：`lineOwner` 是
     上一次 walk 的快照，光靠它写占位符同样可能写出悬空引用。不活 ⇒ 这一行原样推
     （这**不是**体积护栏放弃的，所以不记 `skippedOwnerGuard`）。
   - **只有占位符比原行短才省**（`:451`）—— 否则省了反而更费 token。
   - 其余 ⇒ 原样保留。
4. 一行都没省掉 ⇒ 返回 `null`（不动，`:463`）。
5. 头部（用户给的格式，`:479`）：

   ```
   [<M> 行与第 N 次 <tool> 重复已省略]
   ```

   `N`/`<tool>` 取**贡献省略行最多**的那个 owner（并列取块号小的）。
   ⚠ 省略的行**可能来自多个不同的更早的块**，所以头部只报"最主要的那个"，
   而每一行的精确出处由它自己的占位符给出。**头部是给人/模型看的摘要，占位符才是可机检的凭据。**
6. 输出行数与原行数**完全一致**（被省的行位置上留占位符，不删行）。
   这条让"逐行重建"变成一句无歧义的话。

### 2.5 清理档 ②（对当前上下文做一次清理）

`sweepSession`（`:623`）挂在 `agent/pre-step`（`:1013`）：

1. **便宜的先退出**（`:635`）：`gen` 没变、也没有新的 `tool/result` 落盘 ⇒ 直接返回。
2. **增量 vs 全量**（`:641`）：
   - `st.gen === gen` ⇒ surface 只增不改（`replaceGeneration` 只在**位置替换**时变）⇒ 前 `st.nodeCount`
     个节点原样有效，索引可以续用，只处理新增的那些。
   - 否则 ⇒ **全量重建**索引（`:644`–`:649`）。
3. 按 surface 顺序走每个节点：
   - `assistant/message` ⇒ `harvestToolNames`（`:809`）学 `callId → 工具名`
     （`tool/result` 事件里**没有**工具名，只能这么学）。
   - `tool/result` 且 `isError` / 有 `error` / 非纯文本 ⇒ 跳过（`:685`–`:688`）。
   - 是我们自己换上去的节点（`isOurOutput`，`:692`）⇒ 按它**实际推上去的行**重建索引，
     并且**记进 `ourNodes`**（`:670`，供第 7 步核悬空），然后放过。
   - 其余 ⇒ 登记/复用块，`decideRewrite`，要换就进 `pending`。
4. **先判定、后落盘**（`:745`）：判定用的是"落盘之前的 surface"，
   这正是"第一份还在不在"的真值。
5. 落盘形状**逐条照抄** `dsh-compaction-tool-result-pruner`（`applyReplacement` `:826`）：
   ```
   session.append('compaction/prune', { shadowedRange, shadowedSeqs, shadowedTokenCount })   // :849
   session.append('tool/result', { ...ev.data, message },
                 { surfaceOp: { op:'replace', startSeq, endSeq }, sourceEventSeqs:[seq] })
   ```
   消息用 `freezeMessageLike`（`:194`）冻结；**替换必须更小**（`:831`，原代码里就有这条断言）。
6. `st.gen` 记**落盘之后**的那个值（`:796`）—— 索引描述的正是落盘后的现实。
7. ★ **悬空 owner 的真记账（本轮返工 ①）**（`:772`–`:788`）：走完之后，对第 3 步收下的
   每个 `ourNodes` 跑一次 `auditOurOutput`（`:598`），**悬空就 `danglingOwner += 1`
   ＋ `danglingOwnerNow += 1` ＋ `log('warn', …)`**（日志里带**引用条数**：例如「相似」档那份里 29 个占位符全部取不回）。
   - 为什么放在**走完之后**：`liveBlocks` 要等整趟走完（含落盘那一轮）才反映"落盘后的现实"。
   - 判据是"**它指向的那个 owner 还在不在**"，**不是**"它自己的文本在不在 `textFpToBlock` 里"：
     **指引行的文本永远查不到**（我们从来没把指引文本登记成块）——
     实测 `textFpToBlock.has(fpOf(原文)) === true` 而 `textFpToBlock.has(fpOf(指引文本)) === false`
     ⇒ 照字面写会把**每一条健康的指引行**都记成悬空。详见 `auditOurOutput` 的注释。
   - ⚠ **两个键同时 +1，但口径不同**（这是刻意的，不是重复记账）：
     `danglingOwner`（`:283`）= **历史累计**（只增不减，回答"**有没有发生过**假话"）；
     `danglingOwnerNow`（`:302`）= **本趟 sweep 检出**（每趟**入口**清零，回答"**最近这一趟**核出几条"）。
     累加数只增不减 ⇒ 它回答不了"此刻有没有、有几条"；瞬时键回答这个，但**只统计这一趟
     真正访问到的记号行**（全量重建那趟才等于"整个 surface 上的条数"）——
     完整口径与"为什么两个都留"见 **§8 第 10 条**。
   - 正控 / 判定性实验见自检 **T23**：健康 ⇒ 0 / 0；owner 被搬走 ⇒ 2 / 2；
     **再跑一趟（早退、没重新核）⇒ Now 归 0 而累加仍是 2**（这一步专门把两个口径分开）。

### 2.6 状态模型：块号为什么必须稳定

占位符里写的是**块号**，而它会一直留在上下文里；如果 sweep 每次重建都重新编号，
老占位符就会指到别的块上 ⇒ **有损**。所以：

| 表 | 生命周期 | 用途 |
|---|---|---|
| `blocks`（`:252`） | **永久**（随会话销毁） | 块号 → 块记录 |
| `textFpToBlock`（`:253`） | **永久** | "此刻在上下文里的那段文本"的指纹 → 块号（用来认 surface 节点） |
| `dupIndex`（`:254`） | **永久** | **原文**指纹 → 那个原样块（整块去重查它） |
| `idx.liveDup` / `idx.liveBlocks` / `idx.lineOwner` | **每次 sweep 重建** | 描述"此刻上下文里有什么" |
| `stats.danglingOwner`（`:283`） | **永久·单调累加** | 悬空 owner 的**检出次数**（① 的真记账；回答"有没有发生过假话"，判据见 `auditOurOutput` `:598`） |
| `stats.danglingOwnerNow`（`:302`） | **每趟 sweep 入口清零** | **本趟 sweep 检出的悬空条数**（瞬时键；回答"最近这一趟核出几条"。**只统计这一趟真正访问到的记号行** ⇒ 早退/增量那趟会偏小，口径见 §8 第 10 条） |

块号由 `nextBlockId`（`:311`）单调分配、**永不回收、永不重编**。
`textFpToBlock` 让"同一段文本"在任意次重建之后都指回同一个块号。

**行号**（占位符的第二个数）= 该行在**这个块实际推上去的那份文本**里的 1-based 行号
（`indexNodeText` `:370`）。因为读者（模型）手上有的就是那份文本，按它取行才对得上。

## 4. 哪一档会丢信息、哪一档不会

| 档 | 会不会丢信息 | 为什么 |
|---|---|---|
| 「相同」整块省略 | **不会**（在一条不变量成立时） | 被省略的内容**逐字节等于**上文里那一份，而那一份**此刻还在 surface 上**（`:402` 的 `liveDup` + `liveBlocks` 双重 corroborate，`markLive` `:801`）。硬约束 5 就是这条不变量的守卫。⚠ 见 §7.2 / §7.3 的残余风险 |
| 「相似」按行省略 | **不会**（无条件） | 每个被省的行都留了一个占位符，指向"第一次真正把该行推上去的那个块"的那一行；那个块是**原样**推的、且**此刻还活着**（`:445` 的 `liveBlocks` 校验），它的那行就在上下文里。逐行拼回去**逐字节等于原文** —— 这是自检里的一条断言（T3、E3），不是一句承诺 |
| 两者都没命中 | 不会 | `decideRewrite` 返回 `null` ⇒ **原样返回同一个 `decision` 对象**，一个字节都不改（自检 **T8** 用对象同一性证明） |

**「相似」档为什么可以做到无条件无损**：因为被省掉的行**文本本身没有消失** ——
它在上文那个 owner 块里逐字节躺着，占位符只是"指过去"。
占位符的**行号**指向的是 owner **实际推上去的那份文本**的行号，
所以重建 = 按行号取行，没有歧义、没有猜测、没有递归。

**反过来说：如果某一行在上下文里找不到 owner，它就不会被省。**
这就是为什么"相似"档不可能丢信息 —— 它的省略条件本身就等价于"这行上面有"。

⚠ **但这条"无条件"只对"写下去的那一刻"成立**：记号行一旦写下就**不会再被改**，
而它的 owner 之后**可能被别人搬走**（compaction / 体积剪枝）—— 那时它就成了**悬空**的，
占位符取不回任何一行。这不是"省略条件错了"，而是**追溯性**的（见 §7.3），
并且现在**有记账**：`stats.danglingOwner`（`:283`，判据 `auditOurOutput` `:598`）。

## 5. 零信息损失的精确表述

> 对 surface 上任意一个 tool/result 节点 N，设其原文为 `T`。
> 把 N 在 surface 上的那份文本 `E`（可能是 `T`，可能是头部+占位符，可能是一行指引）
> 按下面的规则展开，得到的字符串**逐字节等于 `T`**：
> - 若 `E` 是一行指引 ⇒ 取它指向的那个 owner 块在 surface 上的那份文本（该块 `verbatim`、且**活着**）；
> - 否则 ⇒ 逐行看 `E`：占位符 `[dup:B:L]` 换成"块 B 那份文本的第 L 行"，其余行原样。

这条规则就是 `context-dedup.selftest.mjs` 里 `verifyZeroLoss()` 做的事，
它读的是**真实运行态**（`state.blocks` / `state.idx.liveBlocks` / `state.textFpToBlock`），
不是测试自己假设的块号。E3 在 20 个节点的合成会话上对**每一份**都跑了这条验证。

## 6. 性能与消耗的取舍

用户逐字：「（用户原话已隐去 —— 公开版不留逐字）」。

### 6.1 每个工具调用的固定开销（实时档 ①）

`tools/post-execute` 里，对**每一个**够大的成功结果：

| 步骤 | 复杂度 | 说明 |
|---|---|---|
| `flattenText`（`:124`） | O(len) | 只拼字符串，无分配 |
| `cpLen`（`:110`） | O(len) | 手写循环，**不** `Array.from`（不分配数组，大字符串也不炸内存） |
| `fpOf`（`:105`） | O(len) | 一次 sha256。实测 100 KB ≈ 0.3 ms |
| `decideRewrite`（`:388`） | O(len) | 一次 `split('\n')` + 每行一次 `Map.get` + 一次 `trim`/正则 |
| 命中才做的额外动作 | O(1) | 查 `liveDup` / `liveBlocks` / `lineOwner`，都是 Map / Set |
| 登记进索引 | O(行数) | 每行一次 `Map.has` + 可能的 `Map.set` |

⇒ **每个工具调用一趟线性扫描，和"我们必须读一遍这段内容"是同一个量级**，
   没有引入任何超线性项，也没有任何 I/O、没有任何 await、没有网络/落盘。
   **不命中重复时一个字节都不改**，所以"没有重复"的会话里它的净效果是 0（只多花一次哈希）。
   ⚠ 本轮返工 ③ 加的两处 `liveBlocks.has(...)` corroborate 是 **O(1) 的 Set 查询**，
   **没有**给热路径引入新的哈希或新的 surface 扫描（见 §7.2 末段）。

### 6.2 每个 step 一次的开销（清理档 ②）

`agent/pre-step` → `sweepSession`（`:623`）：

- **早退**（`:635`）：`gen` 没变且没有新的 `tool/result` ⇒ O(1)，什么都不做。
- **增量**（`:641`）：`gen` 没变 ⇒ 只处理新增节点，O(新增内容)。
- **全量重建**（`:644`–`:649`）：`gen` 变了（有 compaction / 体积剪枝 / 我们自己的改写）⇒ O(整个 surface)。
  全量重建要重算每个 tool/result 的 sha256 并把所有非平凡行重新插进 `lineOwner`。
  **这是本插件最贵的一步**，但它只在"位置替换发生过"的 step 上付一次。
- **悬空核查**（`:772`–`:788`，本轮返工 ①）：只对**这一趟 walk 里见到的、我们自己的记号节点**
  跑 `auditOurOutput`（`:598`）。健康会话里它通常只有几条到几十条，而且**只在真有记号行时**
  才建一次 `buildGuidanceOwnerLookup`（`:566`，O(块数)）；之后每条指引行查它是 **O(1)**、
  每条「相似」档记号行是 O(占位符个数) —— **不会**退化成 O(记号行数 × 块数)。
  ⚠ 它是**记账**，不改变任何判定结果。

### 6.3 实测（本机 Node v22.23.2，全部数字是**跑出来的**）

**每个 step 一次的 sweep 成本**（合成会话，每份结果 ~2 KB / 40 行）：

| surface 规模 | (a) 早退（本 step 没有新的 tool/result） | (b) 增量（有 1 个新结果，gen 没变） | (c) 全量重建（发生过位置替换） |
|---|---|---|---|
| 50 个结果 / 108 KB | 0.037 ms | 0.26 ms | 10.3 / 5.3 ms |
| 200 个结果 / 432 KB | 0.013 ms | 0.11 ms | 36.7 / 21.4 ms |
| 500 个结果 / 1.08 MB | 0.015 ms | 0.12 ms | 60.9 / 50.2 ms |

⇒ **稳态（(a)+(b)）是 0.01–0.3 ms 量级 —— 可以忽略。**
  最贵的 (c) 只在"有人替换过 surface 位置"（compaction / 体积剪枝 / 我们自己的改写）之后付一次。

**单次 sha256**：2 KB → **0.018 ms**；113 KB → **0.66 ms**。

**"省了多少"实测**（合成会话，见报告那一节）：
- 20 个 tool/result（8 相同 + 4 相似 + 8 不同），原文 45458 字符 ⇒ surface 上 23256 字符。
- **省 22202 字符 = 48.84%**（实时档 11 次改写；清理档单独跑也是 48.84% / 11 次）。
- ⚠ **口径：48.84% 是「夹具口径」，不是线上节省率。** 分母是"这 20 个 tool/result 节点的
  原文码点数之和"（45458）。真会话里 surface 上还有 `user/message` / `assistant/message` /
  system 节点，**分母更大**，同一个会话里这个比例只会更低。
  ⇒ **不许把 48.84% 当成线上节省率报**；要报就得同时报分母是什么。
  自检的 E3 输出里也逐字印着这句。
- token 估算（按 4 字符 ≈ 1 token，**仅估算**；字符数是精确的）：省 ~5551。

### 6.4 内存

每个会话的常驻内存 ≈ 所有被索引的非平凡行文本 + 每块一条小记录（几十字节）。
行文本本来就是上下文里已有的内容，这里是**多存一份键**。
`maxIndexedLines`（默认 20 万行）超了按插入顺序 FIFO 淘汰最老的键
（`:374`–`:378`）—— **只降命中率，不改正确性**（被淘汰的行的 owner 还在，
只是后面的块不会再省那一行）。

### 6.5 明确**没有**做的优化（以及为什么）

- **没有**把 `lineOwner` 做成真正增量的：那需要精确知道"哪些节点是实时档已经处理过的"，
  一旦判断错就会把节点判成自己的重复 ⇒ **内容消失**。宁可按 gen 变化做全量重建。
- **没有**做后台线程 / worker：单次哈希是亚毫秒级，起线程的固定成本比它大。
- **没有**给节省设上限（硬约束 7）：不因为"省太多"而停下。

### 7.2 ⚠ 体积剪枝（`toolResultPruner`）会挖掉 owner —— 有护栏，兜底是 pruner 的默认阈值

指引行写的是"**原文在上下文里**"。如果那个 owner 块后来被 DSH 自己的
`dsh-compaction-tool-result-pruner`（按大小剪中间那档，默认 8192 字符）挖掉中间，
这句话就成了假话。

**护栏**（`ownerGuardChars` `:517`）：若 `ctx.get('toolResultPruner')` 在线，
就只对"**不会被它剪到**"的 owner 省略（owner 进上下文那份的码点数 ≤ 它的 `thresholdChars`）；
**取不到服务 / 服务没有可用阈值 / 读取抛错 ⇒ 一律兜底 `PRUNER_DEFAULT_THRESHOLD_CHARS = 8192`**
（`:506`，逐字取自 pruner 自己的 `DEFAULTS.thresholdChars`，该包 `lib/index.js:11`），
**不是 `0`** —— 在本文件里 `guardChars = 0` 的含义是"**不设限**"（判定条件写的是
`guardChars <= 0 || rec.chars <= guardChars`），兜底写 0 就等于**把护栏整个关掉**。
阈值现读现用。
自检 **T17** 两条控（有剪枝器 ⇒ 超阈值的不省；看不见 ⇒ 用 8192 兜底）+ **T22** 四条控
（取不到 ⇒ 8192；取得到 ⇒ 用它自己的；服务在但没阈值 ⇒ 8192；读服务抛错 ⇒ 8192；
外加一条行为控：看不见剪枝器时**超过 8192 的那份不省**，看得见且阈值够大时**照省**）。

⚠ **为什么兜底必须是"更保守"而不是"更省"**（本轮返工 ③ 的核心）：
"取不到服务"**≠**"一定没有剪枝"。护栏失效时用户损失的是：那一份结果的**中段被永久替换成
`[... tool result middle pruned ...]`**，而上下文里只留一行**假话** ——
模型既拿不到原文、也不会去重读。⇒ **少省一点，绝不写假话。**

⚠ 护栏的**启发式成分**：它假设"阈值以内就不会被剪"。
如果 `toolResultPruner` 的配置在两次 sweep 之间被改小、或者有人换了别的剪枝实现，
护栏就可能判断失误。**我做不到**：让护栏去读别的插件的未来行为。

⚠ **"写指引前再核一次 owner 此刻在 surface 上的字节"——我做了哪一半、没做哪一半**（返工 ③）：
- **做了**（`:402` / `:445`）：写指引、写占位符之前，owner 必须**同时被 `idx.liveBlocks`
  corroborate**。这是 O(1) 的 Set 查询，**没有**给热路径加哈希。
- **没做**：在 `tools/post-execute` 热路径上把 owner 的那份文本**从 surface 里再读一遍**并重算
  sha256。理由（可复核）：`liveBlocks` 的成员资格**只能**由一次"全内容 sha256 相符"建立 ——
  `markLive` 只在这两条路上被调用：① 节点的当前文本 `fpOf(text)` 命中
  `textFpToBlock`（`:704` / `:696` / `:962` / `:715`）；② 我们**刚刚亲手写下**这段文本（`:320` / `:339` / 实时档 `:983`）。
  ⇒ "在 `liveBlocks` 里"已经蕴含"surface 上那份的字节 == 记录的那份（按 §2.1 的归一化口径）"。
  唯一能逃过它的场面是：**有人改了 surface 上某个节点的字节、却没有 bump
  `surface.replaceGeneration`**。本部署里**没有这样的写者**：pruner 用
  `surfaceOp.replace`（该包 `lib/index.js:170-180`）、compaction 同理、我们自己的
  `applyReplacement` 也是（`:855`）—— 而实时档在 `gen` 变了时**直接放弃判定**（`:939`）。
  这个残余缺口**如实写在 §8**，没有拿"看起来更严"的代码去掩盖它。

### 7.3 ⚠ compaction / 体积剪枝会把 owner 搬走 —— **两档都会被追溯性打破**（本条我治不了）

`dsh-compaction-basic` 会把一整段历史总结掉（**它本身就是要丢信息的**）。
如果那一段里正好有某个 owner，owner 就没了，而**已经写进日志的记号行还在**。
我**不能**事后把它改回来 —— 内容已经不在了。

⚠ **本条早先只写了「某条指引行指向的 owner」—— 那漏了「相似」档，而且后果一模一样**
（本轮返工 ②）。同一个根因、同一个后果，**两档都中**：

| 记号行 | owner 被搬走后 | 后果 |
|---|---|---|
| 「相同」档的**指引行** | 那一行还写着「**原文在上下文里**」 | 是**假话**：取不回原文 |
| 「相似」档的**占位符** `[dup:B:L]` | 那一份里的**每个**占位符都指向已经不存在的块 B | **取不回任何一行**；若原文只以这份形式存在，那一段内容就没了 |

实测（自检 **T23** 的判定性实验，一条会话里两档同时造）：owner 被从 surface 上搬走后
⇒ `stats.danglingOwner` 从 **0** 变成 **2**（指引行 1 条 + 「相似」档 1 条；瞬时键
`stats.danglingOwnerNow` 同步为 **2**），
而**两条记号行还原样留在 surface 上**（那句假话还在），对「相似」档那份做逐行重建
**抛错**（"占位符指向未知块号"）—— 也就是**一行都取不回**。

⇒ 这同样是 **R41 必须⑤「只在第一份还在上下文里时才省略」被「追溯性」打破**：
写下去的那一刻条件成立，**之后**别人把 owner 搬走了。
我**治不了**它（内容已经不在了，事后改不回来），所以我做的是：
**可机检地报出来** —— `stats.danglingOwner`（`:283`，历史累计）/ `stats.danglingOwnerNow`
（`:302`，本趟检出）+ `log('warn', …)`（`:788`），
判据是 `auditOurOutput`（`:598`），每趟 sweep 走完后核一次（`:772`–`:788`）。

我能做的、也做了的另一半是：**下一次 sweep 会重建索引**，此后**不会再指向**已经不存在的
owner（`liveDup` / `liveBlocks` 重建，`:644`–`:649`；写指引 / 写占位符前还要
`liveBlocks` corroborate，`:402` / `:445`）。
⇒ 影响范围被限制在"**owner 被搬走之前就已经写下去的那些记号行**"。

### 7.6 模块格式：`module.exports` 而不是 `export`（**结论不变，理由已换**）

任务书写的是「`export const name` / `export const inject` / `export function apply(ctx)`」。
**我做成了 CommonJS 的同一形状**：`module.exports = { name, inject, apply, ... }`（`:1124`）。

⚠ **本轮返工 ④：原理由被证伪，理由必须换（结论不变）**。
原理由写的是"本目录没有 `"type": "module"` ⇒ Node 把 `.js` 当 CJS ⇒ 写 `export` 会直接
`SyntaxError`"。**审查在 Node v22.23.2 上实测把这条推翻了**：

```
probe.js（.js，无 package.json，内容是 export const name / export const inject / export function apply）
node --check probe.js        -> EXIT=0（**不是** SyntaxError）
await import('.../probe.js') -> OK -> ["apply","inject","name"]
require('./probe.js')        -> OK -> ["apply","inject","name"]
```

原因：Node **22.7+** 的**模块语法自动探测**默认开启 ⇒ 一个没有 `package.json` 的 `.js`
里写 `export` 不会再被当成 CJS 语法错误。
⇒ **"写 export 会 SyntaxError"这句是错的，不许再拿它当理由。**

**换上去的三条理由**（都不依赖"Node 版本相关的语法探测"）：
1. **有先例、且在生产里活着**：同目录 `warden-watch.js:107` 用的就是这个形状
   （`module.exports = {`），它**已经被 `cordis.patch.yml:13-14` 的 `insert` 行挂着**、
   在本部署里真的在跑。
2. **loader 侧显式兼容**：`cordis-plugin-loader\lib\index.js:522` 在 `_init()` 里对
   `await this.parent.tree.import(...)` 的结果调 `unwrapExports`，而 `unwrapExports`
   定义在 `cordis-plugin-loader\lib\index.js:746-751`，逐字是：
   ```js
   unwrapExports(exports) {
     if (isNullable(exports)) return exports;
     exports = exports.default ?? exports;
     if (!exports.__esModule) return exports;
     return exports.default ?? exports;
   }
   ```
   ⇒ CJS 的 `module.exports = { name, inject, apply }`（没有 `__esModule`）**被显式接受**，
   走 `exports.default ?? exports` 那一支。
3. **不依赖"Node 版本相关的语法探测"**：自动探测是 22.7+ 才默认开启的行为，
   把它当理由等于把插件的可挂载性绑在一个 Node 小版本上；CJS 形状没有这个问题。
- Cordis 侧拿到的是同一个插件契约（`name` / `inject` / `apply`），只是 CJS 的拼法。

⇒ **结论不变：继续用 CJS。** 这是与任务书字面的一处偏离，我如实报告，没有偷偷改。
**"理由错了"不等于"结论错了"** —— 见 §8 的选项。

2. **没有对着真的 `Session` 验证过落盘契约。** 清理档的
   `compaction/prune` + `surfaceOp.replace` + `sourceEventSeqs` 形状是**照抄**
   `dsh-compaction-tool-result-pruner` 的源码写的，自检里的假会话只模拟了
   surface 折叠与 `session/event` 广播，**没有**跑 `Session.append` 的真校验器
   （它还会校验 request-header 字段、tool-error 一致性、遮蔽覆盖完整性）。
   ⇒ **真 append 会不会因为某个字段被拒，没有验证过。**
3. **没有测并行工具调用的竞态**（§7.4）。造这个竞态需要模拟
   `ToolRuntimeScheduler` 的并行派发顺序，我判断收益不抵风险，没有做。
4. **没有测"真 `read` 工具"的端到端**（`exec.agent.session` 的真实对象形状、
   `session.surface.nodes` 在长会话里的实际规模）。E4 用的是假 exec。
5. **`maxIndexedLines` 的 FIFO 淘汰路径没有被单独的自检覆盖。** 代码里有
   （`:374`–`:378`），但我没有造一个超 20 万行的夹具去跑它。
6. **`session/disposed` 之后的 state 清理没有被自检覆盖**（`:1031`）。
7. **没有测"同一个会话里两个 `context-dedup` 实例同时挂载"**（会双重处理）。
   现实中不该发生（patch 里只有一行），但没测。
8. **没有测非 ASCII 行尾/超长行/代理对边界**的 `cpLen` 行为。
   `cpLen` 手写了代理对跳过（`:110`），但只有合成夹具（全是 BMP 字符）跑过。
9. **残余缺口（本轮返工 ③ 的"更强做法"只做了一半，如实写在这里）**：
   "owner 还在不在"的最终判据是 `idx.liveBlocks`，而它**只是上一次 walk 的快照**。
   ⇒ 若有人**改了 surface 上某节点的字节却不 bump `replaceGeneration`**，实时档
   （`:939` 只比 `gen`）不会察觉，仍可能写出"原文在上下文里"的假话。
   **本部署里没有这样的写者**（pruner / compaction / 我们自己的 `applyReplacement`
   一律走 `surfaceOp.replace`，`:855`），但这是**假设**，不是不变量。
   我**没有**在热路径上加"把 owner 的字节从 surface 再读一遍 + 重算 sha256"那一步：
   `liveBlocks` 的成员资格本来就只由一次全内容 sha256 相符建立（§7.2 末段），
   那一步对它**是冗余的**（只会多花一次哈希、并新增一个"查不到就静默不省"的失败面）。
   ⇒ 这个缺口**由记账兜着**：真发生了，下一趟 sweep 的 `stats.danglingOwner` 会把它数出来。
10. **悬空记账的**两个**口径（为什么两个键都留）**：
    - `stats.danglingOwner`（`:283`）= **历史累计**（检出次数，**只增不减**）。它回答的是
      "**有没有发生过**假话"；同一批悬空在又一次**全量重建**时会被再记一次（判据见 `:772`–`:788`）。
      我没有为它加"同一批只记一次"的去重 —— 那需要给悬空节点另存一份 seq 集合，
      收益（读数更漂亮）不抵复杂度。
    - `stats.danglingOwnerNow`（`:302`）= **本趟 sweep 检出的条数**（瞬时键，每趟**入口**清零）。
      它回答的是用户真正会问的那句："**此刻**上下文里有没有假话、有几条"——
      累加数只增不减，回答不了这个问题。
    - ⚠ **瞬时键的诚实边界（必须一起读，否则会误读成 0 = 没有假话）**：它**只统计这一趟
      sweep 真正访问到的记号行**。
      · **全量重建**那一趟访问全部节点 ⇒ 此刻它 = "整个 surface 上的悬空条数"；
      · **增量**那一趟只访问新增节点 ⇒ 老悬空不在计数里；
      · **早退**那一趟（surface 自上次 walk 之后没有任何变化）一个节点都不访问，
        入口清零 ⇒ 它**必然是 0** —— 那表示"**这一趟没检出**"，**不表示"没有"**。
      ⇒ 判"此刻"：`> 0` ⇒ **一定有**；`=== 0` ⇒ 看这一趟是否真的走过（全量重建那趟才是完整的）。
      事实面看 `log('warn', …)`，历史面看 `danglingOwner`。
    - 自检 **T23** 的第三条控（再跑一趟 ⇒ **Now=0 而累加=2**）就是**专门把这两个口径分开**的
      判定性对照；那一趟我还断言了它 `skipped === true`，所以"为什么 Now 是 0"也是机器可查的，
      不是靠这句话解释的。

## 9. 自检怎么跑

```powershell
cd <WORKSPACE>\task-warden\plugin
node --check context-dedup.js          # exit 0
node context-dedup.selftest.mjs        # exit 0 = 全过；exit 1 = 有红
```

- **不碰真账本、不碰真工程、不碰临时区**：全部夹具在内存里造，一个字节都不写盘。
- **25 条判据**，正控 / 负控成对（T1–T21 + **T22** + **T23** + E3 + E4），
  另打印 E3/E4/E5 三段原样输出。
- ⚠ **两个计数别混**（自检汇总里两个都打印）：
  **25 = 判据行数（`RESULTS.length`）**；**断言条数**是 `ok()` + `eq()` 本次实际求值之和
  （一条判据里可能有很多条断言 —— 到底哪一条最多、跑了几条，汇总里**现算现打**）。
  ⚠ 这个"最多的一条"是**现算**的（`test()` 逐条记录断言数，`E3`/`E4` 直接 push、按 0 计），
  **没有写死数字** —— 写死的例子会在改判据后变成过期数字（本项目吃过的 A7）。
  ⇒ 报"25/25 通过"时说的是**判据行数**，别让人以为总共只查了 25 件事。
- ⚠ E3 打印的 **48.84%** 是**夹具口径**（分母只有 20 个 tool/result 节点），
  **不是线上节省率**；自检输出里逐字印着这句（见 §6.3）。
